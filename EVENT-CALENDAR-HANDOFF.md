## End-of-Day Status

Event calendar frontend is live in the dev repo with the main layout and mobile cleanup passes in place.

The calendar now includes:

- Rolling multi-month calendar generated from recurring templates plus one-time events.
- Embedded calendar at `pages/events/` with homepage preview using the same feed.
- Improved month navigation, selected-date summary, grouped upcoming agenda, and mobile-tightened day cells.
- API-backed event loading with static JSON fallback.
- Password-protected event admin wired into the existing DMZ admin token flow.

Today we kept refining the admin experience and restored the event publish path.

Current admin UX:

- Subtle `DMZ Login` trigger remains in the bottom-right footer area.
- After login, the footer trigger enables a lightweight inline edit bar inside the calendar card.
- The edit bar handles publish, reload, reset-to-file, add item actions, logout, and draft-state messaging.
- Clicking a calendar date while edit mode is active opens the full editor in a modal.
- If a clicked date already has a one-time event, that event opens.
- If the clicked date is generated by a recurring template, that template opens.
- If nothing exists for that date, a new one-time draft is created for that date automatically.
- Unsaved changes are now tracked and surfaced in the edit bar.
- Calendar date counts now update live in the embedded view while editing drafts, so same-day add/delete changes are visible before publish.
- The Worker route for event publishing is deployed again, so `Publish` can save to the Worker-backed event store.

What is still rough:

- Public event clicks still redirect to a dedicated event detail page.
- That redirect breaks the flow and feels heavier than it should for simple browsing.
- The next UX pass should keep visitors on the calendar and surface event details in-page.
